## 2. D1. Создание функций

### 2.1. Выбранное решение

Базовые функции - это те, которые можно создавать с помощью фабрики + функции операции. В них заранее реализованы алгоритмы всех базовых функций (взятие производной, нахождение значения и т.д.) TFunction - это надстройка над базовым классом, который имеет все необходимые операции, они перезаписываются. Функции-операции ссылаются на базовые или такие же операции. Для to_string, достаточно рекурсивно вызвать to_string от операндов. Аналогично для нахождения проивзводной и значения в точке.


### 2.3. Отклонённые альтернативы

1. Иметь только базовые функции, а в Tfunction хранить польскую запись из них. Класс фабрики имеет функцию, которая определяет, какую базовую функцию вложить в создаваемый TFunction и функцию регистрации, которая возвращает TFunction с единственной базовой функцией. Так же есть класс в котором либо хранится тип действия, либо базовая функция для вектора в TFunction. Плоха тем, что придется сложно перезаписывать польскую запись в обычную и еще хуже считается производная.
2. В фабрике хранится map из lambda функций-создателей. Обращение происходит удобно по ключу. Плоха тем, что не ясно, точно, как просто создавать комбинации функций через действия.

### 2.4. Что не меняется при добавлении новой функции

Фабрика не меняется. Меняется только base_func (добавляется новая базовая функция с реализациями + выбор базовой функции в спец функции-определителе).

## 3. D2. Владение и время жизни

### 3.1. Выбранное решение

TFunction хранит shared_ptr на базовую функцию. Внутри функций операций так же shared_ptr на операнды. При копировании или присваивании, дается shared_ptr, ссылающийся на те же объекты.

### 3.2. Отклонённые альтернативы

1. Не использовать shared_ptr. Плохо, так как требуется сложное рекурсивное копирование.
2. shared_ptr только на листья плохой вариант, так как при планируемом рекурсивном вычислении производных и значений будет нужна сложная обработка типа (функция-операция или базовая типовая функция).

### 3.3. Недостаток выбранного варианта

Разделяемое владение означает, что выражение не освобождает память, пока жива хотя бы одна копия. Пик памяти определяется наиболее долгоживущими выражениями.

## 4. D3. Идентификация типов и ошибки

### 4.1. Выбранное решение

Перегрузка функций типами. Не совпаденние строк и типов в перегруженной версии создает ошибку.

### 4.2. Отклонённые альтернативы

1. std::variant. Плохо тем, что нужно проверять все соответствия типа variant со строкой.
2. Строка как шаблонный параметр (fabric.create<'type'>(param)). Не соответсвтует примеру.
3. Функция классо-определитель. Слишком сложное и большое количество проверок по типу.

### 4.3. Недостаток выбранного варианта

При добавлении новых базовых функций могут усложниться текущие перегузки функций, но для необходимых в реализации вариантов приемлемый вариант.
